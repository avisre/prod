## Part C — the RIA leg: honest status, not a fabricated list

**I did not fabricate RIA names, and here's why that would have been worse than
useless.** SEC IAPD (`adviserinfo.sec.gov`) is the correct public source v3 named,
but it's a JS search application — a plain fetch returns only the page shell, not
adviser rows. Getting real small-RIA names requires driving the actual search form
(state + AUM-range filters), which needs an interactive/headless-browser session,
not a one-shot web fetch. Producing 7 plausible-sounding firm names without that
would be indistinguishable from making them up, and outreach on invented identities
is worse than no outreach at all.

**The exact recipe for whoever runs this next (Playwright, same pattern as the
Brave-profile-clone recipe used for AppSumo/GA4):**
1. `https://adviserinfo.sec.gov/search/genericsearch` → Firm search → filter AUM
   $25M–$150M (small RIA range, per v3), state = a few target states.
2. For each result, open the firm's IAPD summary page → Form ADV Part 2A ("brochure")
   → confirm it's a single-name or small (1–3 person) advisory shop, not a captive
   arm of a bank/broker.
3. The brochure's cover page is legally required to carry a contact
   name/phone/address — that's the real, compliant contact point, not a guessed
   email.

This yields genuinely real names in under an hour of interactive work; it just isn't
something a single WebFetch call against a JS app can produce, and I'd rather flag
that cleanly than hand over invented firms.
